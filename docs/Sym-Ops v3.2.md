# Sym-Ops v3.2: 生産性強化版

v2のエラー耐性を継承しつつ、YAMLサポート・バッチ実行・自動修復機能を追加した実装版です。

---

## 1. 問題点の再分析

### Sym-Ops v1 の致命的弱点

| 問題 | 原因 | 影響 |
|:---|:---|:---|
| `--` の衝突 | Markdown/SQL/Diffと混同 | 15%の失敗 |
| 記号の欠落 | `$` `@` の省略 | 14%の失敗 |
| 連鎖破綻 | 1箇所のミスが全体に波及 | 回復不能 |
| 空白の曖昧性 | `$ create@file` vs `$ create @ file` | 8%の失敗 |

---

## 2. Sym-Ops v3.2 設計原則

### 設計目標

1. **衝突ゼロ**: コード内に絶対出現しない区切り文字
2. **記号の冗長性**: 1文字の記号を避け、2-3文字に
3. **エラー局所化**: 1セクションの失敗が他に波及しない
4. **自己記述性**: 記号自体に意味を持たせる
5. **自動修復**: 誤生成を自動補正するファジーパーサー
6. **YAMLサポート**: 複雑な引数をYAML形式で指定可能

---

## 3. Sym-Ops v3.2 構文定義

### 3.1 基本記号

| 記号 | 意味 | 使用例 |
|:---:|:---|:---|
| `>>` | 推論 (Thought) | `>> ユーザー認証を実装する` |
| `::` | アクション (Action) | `::write_file @auth.py` |
| `@` | ターゲットパス | `@path/to/file.py` |
| `<<<` | コンテンツブロック開始 | `<<<` |
| `>>>` | コンテンツブロック終了 | `>>>` (列0のみ認識) |
| `%%%` | バッチ区切り | `%%%` (execute_batch内) |

### 3.2 バイタル (Vitals)

| 記号 | 意味 | 範囲 |
|:---:|:---|:---|
| `::c` | Confidence (信頼度) | 0.0 - 1.0 |
| `::s` | Safety (安全性) | 0.0 - 1.0 |
| `::m` | Memory (メモリ使用量) | 0.0 - 1.0 |
| `::f` | Focus (集中力) | 0.0 - 1.0 |

```
::c0.88 ::s1.0 ::m0.1 ::f0.95
```

### 3.3 完全な構文例

```
>> ユーザー認証システムを実装する
>> セキュリティ要件: bcryptでハッシュ化

::c0.88 ::s1.0 ::m0.1 ::f0.95

::write_file @auth.py
import bcrypt

def hash_password(password: str) -> bytes:
    salt = bcrypt.gensalt(rounds=12)
    return bcrypt.hashpw(password.encode(), salt)
